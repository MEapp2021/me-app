# 送信機チェック

テレメータ送信機（心電図送信機）の所在確認と点検記録をするアプリです。

- 画面：GitHub Pages（このフォルダの `index.html`）
  URL：https://meapp2021.github.io/me-app/telemetry/
- データ：Googleスプレッドシート（me2021.gasu@gmail.com）
- つなぎ役：GAS（`gas/code.gs` をスプレッドシートに貼り付けて使う）

## 仕組み

- 記録ボタンを押すと、画面にはすぐ反映されます。スプレッドシートへの書き込みは裏で行います（送信箱）。
- 電波がない間は、記録を端末にためておきます。つながったら自動で送ります。画面右上に「保存済み／送信中◯件／オフライン・◯件待ち」が出ます。
- 一度開いた端末なら、電波がなくてもアプリを開けます（`sw.js` が画面を端末に保存しています）。
- 最初に5桁のユーザー番号でログインします。番号は「スタッフ」シートで決めます。記録者の名前はGASが番号から付けるので、なりすましや入れ忘れが起きません。
- 権限が「管理者」の人だけ、設定画面（部署・チャネルの登録や変更、未点検の日数、QRラベル印刷）を使えます。未登録チャネルの新規登録は全員ができます。
- 所在の移動（貸出・返却）は点検とは別に記録します。集計の「いまの状態」に貸出中の一覧（貸出先・何日目か）が出ます。
- 一括記録は集計で「一括」として、実際に点検した件数と分けて数えます。
- 送信機に貼るQRラベルを印刷でき、「QRで読む」で読み取れます（中身は「TX-1001」の形）。

## はじめての設定（1回だけ）

1. **スプレッドシートを作る**
   Googleドライブ（me2021.gasu@gmail.com）で、新しいスプレッドシート「送信機チェック」を作ります。
   今ある台帳を使う場合は、「送信機チャネル台帳.xlsx」をドライブにアップロードして、Googleスプレッドシートとして開きます（「チャネル台帳」「部署」シートが入った状態）。
2. **GASを貼る**
   スプレッドシートの「拡張機能 → Apps Script」を開き、`gas/code.gs` の中身を全部貼り付けて保存します。
3. **初期設定を実行**
   上の関数の選択で「初期設定」を選んで「実行」。初回は権限の確認が出るので許可します。
   シート（送信機マスタ・部署マスタ・点検履歴・最新状態・スタッフ）ができ、「チャネル台帳」「部署」があれば中身が写されます。
4. **スタッフを入れる**
   「スタッフ」シートに、A列：名前、B列：5桁の番号、C列：権限（管理者なら「管理者」、それ以外は空欄）を入れます。
   直した内容は5分以内に反映されます。すぐ反映したいときは関数「スタッフの変更を反映」を実行します。
5. **ウェブアプリとして公開**
   「デプロイ → 新しいデプロイ → 種類：ウェブアプリ」
   実行ユーザー：自分／アクセスできるユーザー：全員 →「デプロイ」。
   表示された `https://script.google.com/macros/s/…/exec` をコピーします。
6. **画面にURLを入れる**
   `telemetry/index.html` の `const API_URL = '';` の '' の中に貼ってコミットします。
   （とりあえず試すだけなら、ログイン画面に出るURL欄に貼っても動きます。その端末だけに保存されます）

## GASを直したとき

「デプロイ → デプロイを管理 → 鉛筆 → バージョン：新バージョン → デプロイ」。
こうするとURLが変わらないので、画面側の修正はいりません。

## シートの中身

| シート | 列 | メモ |

| 部署マスタ | 部署 / 表示順 / 受信側の枠数 / 備考 | 表示順の小さい順に並びます。枠数と備考はアプリからも入れられます |

| 最新状態 | CH / 所在 / 所在の更新 / 最終点検 / 管理状況 / 点検結果1 / 点検結果2 / 点検者 / 貸出日時 | CHごとの今の所在と最後の点検。自動で書き換わるので手で直さない |

## 部署ごとのCH一覧（A4・1部署1枚）

集計画面の「部署ごとのCH一覧を印刷（1部署1枚）」で、押した瞬間の所在をもとに、1部署を1枚のA4にまとめます。上の選択で「全部署」か1部署を選べます。
- 上段：在室のCH数・受信側の枠数・空き枠（超えると「枠を超過」）・使用中・要対応（修理中・紛失・汚染・破損）。
- 中段：受信枠の数だけ箱が並び、在室のCHが入ります。色は状態（青＝使用中、緑＝保管中、赤＝要対応）。空いた枠は点線の「空き」、枠を超えたCHは赤い点線の「枠外」。
- 下段：備考。押すと書き込め、部署マスタに保存されます。空欄なら手書き用の罫線で印刷されます。
- 枠数は「設定 → 部署と受信側の枠数」で管理者が入れます。CHが多い部署は1枚に収まるよう箱が自動で小さくなります。
- 印刷はパソコンのChromeがおすすめです（用紙A4・余白なし・背景のグラフィックをオン）。

## 未点検の一覧と紙の確認表

- 点検画面の「未点検」ボタン（件数付き）で、最後の点検から設定の日数以上たったCHを部署ごとに一覧します（修理中・紛失は除く、古い順）。押すとそのまま点検できます。
- 一覧の「紙の確認表（PDF・印刷）」で、A4の記入表を出せます。列は No・日付（手書き）・CH・部署・前回の点検・状態（○をつける）・確認者・備考。1枚25行。
  - 「未点検のCHを印字」：CHと部署が印字され、日付と状態を書き込みます。部署ごとに改ページできます。
  - 「空欄（すべて手書き）」：日付・CH・部署も手書きする白紙の表。
- 「所在確認シート：全CHを1枚に」：登録している全CHを印字。CHの下に最新の確認日、所在欄の左上に前回の所在を薄く印字し、所在（同じなら ✓）と状態（○使用中 △保管中 ×修理 ？見つからない。異常はア＝アラーム、汚＝汚染、破＝破損を後ろに付ける）を手書きします。CH番号順／部署順、「1枚に収める」（約230台まで6列）／「2枚（記入欄を大きく）」を選べます。登録にないCHを書く空欄付き。
- PDFにするときは、印刷画面でプリンターの代わりに「PDFに保存」を選びます。

## 稼働率などの集計

集計画面（日・週・月・年）と、部署別A4の「月次の集計」に出ます。計算はGAS（関数 stats_）が行います。
- **稼働率**＝使用中だったCH・日数 ÷（CH数 × 日数）。各日の状態は「その日までの最後の記録」で決めます（点検のない日は前の状態が続いたとみなす）。
- **平均使用／最大使用**：1日あたりの使用中の台数の平均と最大。
- **枠使用率**＝平均在室台数 ÷ 受信側の枠数（100%を超えると、枠より多い送信機がその部署にある）。
- **点検した日の割合**＝点検（一括を含む）があったCH・日数 ÷ 在室のCH・日数。
- **異常**：アラーム（不整脈・上下限・テクニカル）、破損・汚染・清掃未実施、紛失の件数。
- CSV（チャネル別・部署別）にも稼働率などの列が入ります。
- 点検の間があくほど推定の部分が増えます。毎日点検していれば、ほぼ実際の値です。

## 画面の使い方のコツ

- 画面は上のメニューが固定され、中だけがスクロールします。
- スマホではCHを入れるとテンキーがたたまれ、点検の入力欄が広がります。番号の欄を押すとテンキーに戻ります。
- 今日の記録は、パソコン・横長のタブレットでは右の列に、スマホでは点検画面の「今日の記録」ボタンから開きます。
- 記録を押すと編集・削除ができます。直せるのは記録した本人と管理者だけです（GASでも確認しています）。編集できるのは今日の記録で、古い記録はスプレッドシートで直します。

## 点検項目

| 管理状況 | 点検結果1 | 点検結果2 |
|---|---|---|
| 使用中 | アラーム：問題なし／不整脈／上下限／テクニカル | テクニカルのとき：電池交換／電池切れ／電極確認／電波切れ／その他 |
| 保管中 | 本体・ケーブル：正常／破損／汚染 | 清掃・消毒：実施／未実施 |
| 修理中・その他 | （コメント必須） | |
| 紛失 | | |

## 年に1回くらい

点検履歴が増えて重くなったら、Apps Scriptで関数「前年までをアーカイブ」を実行します。
前年までの行が別のスプレッドシート「送信機点検履歴_◯年まで」に移ります。

## 画面を大きく直したとき

`sw.js` の `VERSION`（例：`tx-me-v1` → `tx-me-v2`）を上げると、各端末に保存された古い画面が入れ替わります。

## ME業務ダッシュボードに出す

送信機チェックのGASは、合言葉（「設定」シートのAPIキー）付きで要約を返します。
ME業務ダッシュボードのGASに次の関数を足して、要約を読み込んでください（URLとキーは自分のものに置き換え）。

```javascript
function 送信機チェックの要約() {
  const url = 'https://script.google.com/macros/s/…/exec';   // 送信機チェックのGASのURL
  const key = '…';                                           // 送信機チェックの「設定」シートのAPIキー
  const res = UrlFetchApp.fetch(url, { method: 'post', contentType: 'text/plain', payload: JSON.stringify({ action: 'summary', key }), muteHttpExceptions: true });
  const r = JSON.parse(res.getContentText());
  if (!r.ok) throw new Error(r.error);
  return r.data;
  // 例：{ at:'2026/11/25 12:00', total:212, doneToday:180, overdue:12, overdueDays:1,
  //       items:[{ ch:'1063', kind:'汚染', where:'6B東', days:3 }, { ch:'1074', kind:'貸出中', where:'北3', days:82 }] }
}
```

`items` の kind は「紛失」「修理中」「破損」「汚染」「貸出中」です。ダッシュボードの要対応に並べると、病棟に出ている送信機の状況が一目でわかります。
